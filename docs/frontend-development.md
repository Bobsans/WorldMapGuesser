# Разработка фронтенда

Исходники фронтенда находятся в `web/src`, его конфиги и npm-пакет — в `web`, текущий backend — в `server`. См. [код-стайл](code-style.md).

Фронтенд переведён на Vue 3, TypeScript, Vite и Sass (синтаксис SCSS). Форматирование задают `.editorconfig`, ESLint и Stylelint: два пробела, порядок `template → script → style`, обязательные фигурные скобки и K&R. Стили глобальные, с классами компонентов; `scoped` запрещён правилом ESLint. Глобальный event bus и Vue filters заменены props/emits и типизированными функциями. `svg-pan-zoom` заменён собственными Pointer Events и математикой SVG viewBox.

## Окружение и команды

Нужны Node.js 24 и npm. Все npm-команды ниже выполняются из `web`; из корня можно использовать `npm --prefix web run <command>`. Версии зависимостей зафиксированы в `web/package.json` и `web/package-lock.json`.

```sh
cd web
npm ci
npm run dev
```

Vite запускается на `127.0.0.1:8300`. `/get-top` и `/send-score` проксируются на `http://127.0.0.1:8280`. Для другого адреса backend нужно задать переменную окружения `API_PROXY_TARGET` перед запуском Vite. Ключи доступа в неё не помещаются.

Доступный legacy backend можно запустить командой `python server/main.py --port 8280 --debug` из корня репозитория в совместимом Python-окружении. Обновление Bottle и замена Python на Go являются следующими этапами. При недоступном API интерфейс показывает ошибку рейтинга/сохранения, а не выдаёт неуспешное сохранение за успешное.

| Команда                                                               | Назначение                                                                      |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `npm run type-check`                                                  | Строгая проверка TypeScript и Vue SFC                                           |
| `npm run lint`                                                        | ESLint flat config: JS, TS, Vue и запрет scoped styles                          |
| `npm run stylelint`                                                   | Stylelint для глобальных SCSS-файлов и Sass-блоков Vue                          |
| `npm run format` | Автоисправление ESLint и Stylelint |
| `npm test`                                                            | Vitest: правила партии, время, SVG-координаты и контракт API                    |
| `npm run build`                                                       | Проверка типов и production-сборка в `web/dist`                                 |
| `npm run check`                                                       | Линтеры, форматирование, unit-тесты, типы и сборка                              |
| `npm run preview`                                                     | Локальный просмотр production-сборки на `127.0.0.1:8301/static/`                |
| `npm run test:e2e`                                                    | Playwright: production-сборка на desktop и мобильном viewport                   |
| `python -m unittest discover -s server/tests -v` из корня репозитория | Совместимость реального Vite manifest с Python-шаблоном; запускать после сборки |

Перед первым браузерным прогоном установить Chromium командой `npx playwright install chromium`. В CI Linux для зависимостей браузера используется `npx playwright install --with-deps chromium`. Playwright сам запускает и закрывает preview-сервер. Рабочая база не нужна: E2E используют явные ответы API-фикстур. Сценарий победы использует короткий каталог из исходных контуров; полный каталог из 256 стран проверяется отдельно.

На TypeScript 7 переход пока не выполнен: актуальный `typescript-eslint` 8.72.0 поддерживает TypeScript ниже 6.1. Выбран последний совместимый стабильный TypeScript 6.0.3. Остальные прямые зависимости обновлены до проверенных стабильных версий на 23 октября 2026 года.

## Сборка и текущий backend

- `web/index.html` — entrypoint Vite. Production-файлы используют префикс `/static/`.
- `web/dist/index.html` готов к дальнейшему включению в Go-бинарник вместе со всеми ресурсами `web/dist`.
- Большой исходный `web/src/assets/data/countries.json` поставляется отдельным хешированным JSON-ресурсом, а не дублируется внутри JavaScript. Исходный каталог не изменён.
- Шрифты Comfortaa берутся из npm-пакета и входят в статическую сборку; обязательного запроса к Google Fonts нет.
- Vite пишет нативный manifest в `web/dist/statics.json`. Временная интеграция в `server/app/templateloader.py` читает его и подключает ESM entrypoint через `type="module"`, включая CSS импортированных чанков.
- Legacy-форма Webpack manifest пока также читается загрузчиком. Сам Webpack и его инструменты из фронтенда удалены.
- При production-запуске с текущим backend Nginx должен раздавать `/static/` из `web/dist` (либо из `static` в плоской legacy-установке). В этапе Go раздача перейдёт приложению.
- `/get-top` и `/send-score` и JSON-форма результатов сохранены. Серверная проверка сессий и идемпотентность относятся к этапу Go и сейчас не реализованы. Неоднозначно завершившийся POST автоматически не повторяется, чтобы старый API не создавал дубликаты.

## Состояние игры и управление

`web/src/scripts/game.ts` содержит чистые правила партии. Три жизни, подсчёт правильных ответов, переключение заданий, окрашивание ожидаемой страны при ошибке и топ-10 сохранены. После всех заданий наступает победа, после третьей ошибки — поражение. Завершённая партия сразу останавливает таймер; сетевой запрос не задерживает экран результата. При рестарте старый запрос не может изменить статус новой партии.

`web/src/scripts/map-viewport.ts` отвечает за масштаб, координаты с учётом SVG letterboxing и границы перемещения. `WorldMap.vue` обрабатывает мышь, колесо, один/два пальца, pointer capture и отмену жестов. Перетаскивание и pinch не считаются ответом. Есть кнопки масштаба и возврата к обзору. Смена размеров окна не сбрасывает текущее положение карты.

Интерфейс адаптирован к узким экранам: перестраиваются header, подсказки и информация preview, диалоги прокручиваются, кнопки рассчитаны на сенсорное управление. Автоматические мобильные проверки выполняются в Chromium-эмуляции. Проверки на физических Android/iOS и отдельный WebKit-прогон остаются частью последующей мобильной приёмки.
